# Веха-8: честное поглощение nb-чисел операторами (TKT-052)

Дата: 2026-11-06. Стадии: сплайс `Compiler/stage1_compiler.kt`, бинарь 16 989 Б → новые пробы.

## Зачем
Веха-7 дала многозначные числа, но каждый адрес/значение стоил 6 байт CONST:
`nb 3 4 ne sv va` грузит 34, потом `sv`/`va` работают СЛОТОМ (W_Current) —
адрес пришлось второй раз набирать словами. Веха-8: оператор памяти поглощает
ОТКРЫТОЕ nb-число как свой честный операнд — одна конструкция «число → оператор».

## Честное правило
`nb d d ... X`, где X ∈ {'sv','va','gp','sp'}:
- 'sv'   → OP_STORE_AT 0x55 + BE32(Num_Acc): cell[адрес] = acc. 5 Б.
- 'va'   → OP_LOAD 0x12 + 0x19 + BE32(Num_Acc): acc = cell[адрес]. 6 Б.
- 'gp'   → OP_INCELL_IND 0x52 + BE32(Num_Acc): acc = cell[cell[адрес]]. 5 Б.
- 'sp'   → OP_STORE_IND 0x53 + BE32(Num_Acc): cell[cell[адрес]] = acc. 5 Б.
После поглощения: Num_Pending = 0, Num_Acc = 0. Длина эмиссии НЕ меняется
(операнд заменяется с BE32(W_Current) на BE32(Num_Acc)) — честных новых байтов нет.
`nb d ... ne` остаётся честной константой → acc (веха-7, без изменений).

## Новый честный брак: BRK_NB_NO_CONS 0x0C
Оператор, который число поглотить не может, при открытом nb-числе — честный
брак fail-fast (позиция = текущее слово): 'se','st','fu','ru','wc','eq','gt',
'lt','ad','su','if','es','te'. Открытое число может быть потреблено только
четвёркой поглотителей или закрыто 'ne'.

## Честные границы (не трогаем, pre-existing)
- 'pr' НЕ поглощает: честный смысл 'pr' — показать ТЕКУЩИЙ слот; адресного
  операнда у него нет → открытое число при 'pr' живёт как в вехе-7 (хвост 0x09).
- Фигурные скобки/';' при открытом числе — хвост 0x09 (как в вехе-7).
- `wc` перед nb-числом (`wc sv`) — pre-existing путаница pendings, не адресуем.

## Пробы
- `pos_oper.words`: `nb 5 ne nb 6 sv nb 6 va ad 1 sv pr te` (14 слов) →
  CONST 5 → cell[6]=5 (поглощённый sv) → acc=cell[6]=5 (поглощённый va) →
  +1 = 6 → cell[WORK]=6 (обычный sv) → порт ← 6; SUCCESS. Байт-assert:
  STORE_AT BE32(0x06), LOAD 0x19 BE32(0x06).
- `pos_oper2.words`: `nb 7 ne nb 7 sv nb 7 gp sv pr te` (11 слов) →
  cell[7]=7 → acc=cell[cell[7]]=7 → cell[WORK]=7 → порт ← 7. Байт-assert:
  STORE_AT BE32(0x07), INCELL_IND BE32(0x07).
- `neg_oper1.words`: `nb 5 ad 7 ne pr te` → 0x0C@2, вердец 0xFE.
- `neg_oper2.words`: `nb 1 2 3 4 te` → 0x0C@5, вердец 0xFE.

## Честная эволюция neg_num1 (вехи-7 -> вехи-8)
`nb 3 4 pr te`: в вехи-7 'pr' не браковал открытое число, хвост давал 0x09@0
(вердец 0xFF). В вехи-8 'te' получил честный guard — брак честно переносится
на 'te': 0x0C@4, вердец 0xFE. Хвост-брак 0x09 теперь недостижим для
'te'-программ (остаётся только для Nb-числа, заканчивающего исходник `nb d d .`).

neg_num1 0x09@0 / neg_num2 0x0A@0 / neg_num3 0x0B@2; холодный ход exit 0.
Стенд stage1_selftest.kt не тронут (как в вехах 6/7).
