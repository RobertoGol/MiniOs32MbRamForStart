# веха-7 (TKT-052): многозначные литералы — дизайн

## Задача
Буфер исходника слово-языка принимает числа только 0..9.
Для grow (адреса слотов, счётчики) нужен литерал >9 без умножения.

## Факты площадки
1. VM режимы OP_LOAD: 0x14 конст+ ; 0x15 ячейка+ ; 0x17 конст- ; 0x18 сравнить-ячейка.
2. KINII стадия-0: `имя = имя + имя` работает (эмиссия режима 0x15).
3. Умножения нет. Значит d1*10 = 10 сложений d1.
4. Слова: максимум 2 символа, разделитель — один пробел.
5. Числа разделяются пробелами, значит 2 цифры = 2 слова.

## Решение (минимальное честное, без умножения)
Три новых слова:
- `nb` (num begin): Num_Acc = 0, Num_Pending = 1. Байт не эмитит.
- цифра d при Num_Pending=1 (сайт D0..D9, ЧИСТАЯ копия):
  Nine_Tmp = Num_Acc; Num_New = 0;
  Num_New = Num_New + Nine_Tmp; (x10 строк, честная десятка)
  Num_New = Num_New + d;
  Num_Acc = Num_New.
- `ne` (num end): эмитит OP_CONST + BE32(Num_Acc), Num_Pending = 0.

## Браки (честные коды, продолжают серию 0x0x)
- `digits` без `nb` в конце исходника -> BRK_NUM_NO_BEGIN 0x09 @ цифра.
- `ne` без `nb` -> BRK_NUM_NOT_OPEN 0x0A @ ne.
- `nb nb` -> второй nb сброс без брака? НЕТ: NB при активном честном
  Num_Pending -> BRK_NUM_NESTED 0x0B @ второй nb (fail-fast).
- лимит числа: BE32 в VM (0xFFFFFFFF максимум); отдельного кода не нужно.
