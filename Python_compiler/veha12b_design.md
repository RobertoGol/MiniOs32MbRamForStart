# Веха-12б: честное умножение 'ml' (TKT-052)

Дата: 2026-11-07. Статус: ✅ сделано (компилятор 19 179 → 20 564 Б).

Решение пользователя: 12б = умножение `ml` (вариант 1) **+ часть самосборки**
(вариант 2). Реализация — честное runtime-кольцо на уже существующих опкодах
VM (12а дала `mk`/`jb`, но кольцу они не понадобились: все цели статичны).

## Слово и семантика

`ml N`, где N — **одна цифра 0..9** (следующее слово-литерал):

- `ml` байта НЕ эмитит: ставит честный pending-режим `Op_Pending = 0x90`,
  `Op_Position = Word_Index`, `Token_Counter += 1`, `Found_Flag = 1`.
- следующая цифра: `Ml_Mult = Lit_Value`, затем `Emit_Ml_Ring()`.
- смысл: `acc := acc * N` (32-бит, переполнение честно по модулю 2^32 — VM).

Композиция работает: `ml 3 ml 4` = `acc * 12` (линейно, без вложенности).

## Байтовая раскладка кольца (эмиссия ровно 92 Б)

`L0` = эмиссионный адрес тела кольца = `Emitted_Bytes + 25`.
Файловый адрес любой цели = эмиссионный адрес + 20 (заголовок v1.1).

| # | Смещение | Байты | Опкод | Смысл |
|---|---|---|---|---|
| setup | +0 | 5 | `0x55 BE32(TMP_X)` | TMP_X <- acc (множимое) |
| setup | +5 | 5 | `0x15 BE32(N)` | acc <- множитель |
| setup | +10 | 5 | `0x55 BE32(TMP_CNT)` | TMP_CNT <- N |
| setup | +15 | 5 | `0x15 BE32(0)` | acc <- 0 |
| setup | +20 | 5 | `0x55 BE32(TMP_ACC)` | TMP_ACC <- 0 (накопитель) |
| тело | L0+0 | 6 | `0x12 0x19 BE32(TMP_CNT)` | acc <- счётчик |
| тело | L0+6 | 6 | `0x12 0x16 BE32(0)` | acc <- (счётчик == 0) |
| тело | L0+12 | 5 | `0x06 BE32(L0+22+20)` | JZ: счётчик != 0 -> body_add |
| тело | L0+17 | 5 | `0x07 BE32(L0+61+20)` | JMP: счётчик == 0 -> EXIT |
| body_add | L0+22 | 6 | `0x12 0x19 BE32(TMP_ACC)` | acc <- накопитель |
| body_add | L0+28 | 6 | `0x12 0x15 BE32(TMP_X)` | acc += множимое (режим «+ячейка») |
| body_add | L0+34 | 5 | `0x55 BE32(TMP_ACC)` | накопитель <- acc |
| body_add | L0+39 | 6 | `0x12 0x19 BE32(TMP_CNT)` | acc <- счётчик |
| body_add | L0+45 | 6 | `0x12 0x17 BE32(1)` | acc -= 1 |
| body_add | L0+51 | 5 | `0x55 BE32(TMP_CNT)` | счётчик <- acc |
| body_add | L0+56 | 5 | `0x07 BE32(L0+20)` | JMP назад на тело |
| EXIT | L0+61 | 6 | `0x12 0x19 BE32(TMP_ACC)` | acc <- произведение |

Итого: 25 (setup) + 22 (тело) + 39 (body_add) + 6 (EXIT) = **92 Б**.

Цели известны в момент эмиссии, поэтому **патч-фаза не нужна** (в отличие от
if/es): JZ/два JMP пишут готовые BE32-адреса.

## Честные TMP-ячейки

| Адрес | Имя | Смысл |
|---|---|---|
| 0x00F00FF9 | TMP_CNT | счётчик кольца `ml` |
| 0x00F00FFA | TMP_ACC | накопитель произведения |
| 0x00F00FFB | TMP_X | множимое (копия acc) |

Свободны (за W7 0x00F00FF8), в честный номинал `wc` не входят.

## Честные браки

| Код | Условие | Вердец/позиция |
|---|---|---|
| `0x0C BRK_NB_NO_CONS` | `ml` при открытом nb-числе — не поглощает | 0xFE, fail-fast, позиция = `ml` |
| `0x06 BRK_EQ_NO_LIT` | `ml` при уже занятом `Op_Pending` (два оператора подряд) | 0xFE, fail-fast, позиция = `ml` |
| `0x0F BRK_ML_NO_LIT` | `ml` без цифры-множителя до конца исходника | 0xFF (pre-existing хвост-раскладка: вердец пишется до хвост-проверки), Error=1, позиция = `ml` |

Новый код `0x0F` (BRK_ML_NO_LIT) — единственный добавленный брак вехи.

## Честные границы

- Множитель — **только одна цифра 0..9**; для ×12 — композиция `ml 3 ml 4`.
- Кольцо линейное: `ml` не вкладывается в выражение (стадия-0 без выражений).
- TMP-ячейки глобальны: два `ml` подряд безопасны (первое кольцо завершается
  до второго), вложенных `ml` нет.
- `nb X ne ml d` законно (`ne` закрывает число, `ml` берёт свою цифру).

## Честные уроки

1. **Порядок байтов KW-констант**: `ml` = `0x6C6D` (второй символ в старшем
   байте). Первая сборка с `0x6D6C` дала честный `0x01@3` (неизвестное слово).
2. **D015 стадии-0**: `out_cell` не принимает переменную. Байтовый канал
   кольца — `log_cell(STREAM_EMIT_CELL, var) + sys_call(FILE_U8)` (как в
   цифровых сайтах режима `Op_Pending`).
3. **Статичные цели** избавили от патч-фазы: длина кольца фиксирована (92 Б),
   поэтому JZ/JMP пишутся готовыми адресами.
4. **`--source` = поток FILE_GET, а не прекэргрузка буфера**: отдельный прогон
   артефакта видит `cell[SOURCE_CODE_BUFFER] = 0`. Проба «адрес-как-данные»
   (`probe_addr`) поэтому НЕ критерий для standalone-артефакта; чтение
   SOURCE_CODE_BUFFER возможно только в том же процессе, который сам его
   загрузил (это делает `Boot_Load_Loop` компилятора — путь самосборки).
   Проба удалена как нечестная по постановке.
