# Спринт А планировщика: честные Task/очереди (TKT-055)

Дата: 2026-11-07. Статус: 🟡 дизайн (код VM/ядра НЕ менялся).
Родитель-спека: `CtOs/SCHED_SPEC.md` (этап А — «структура Task + очереди,
честные тесты spawn → yield → join → exit на VM»).
Конфликт-граница: пока параллельная сессия работает над вехами 12в/12г
компилятора стадий — правки только в VM (`CtOs-Emu/ctos_vm.py`) и ядре на
стадии-0; ячейки-адреса новые, поверх честной карты Readme Appendum 2026-11.

## Честная постановка спринта А

Ядро (`kernel.ctos`, собирается стадией-0) ведёт честную таблицу задач и
очереди; VM выполняет ТОЛЬКО механику переключения контекстов (как процессор
и аппаратный таймер, всё остальное — код ядра). Никакой логики выбора задач
в VM нет — это честная граница слоёв.

## Честная модель задач (структура, спека §1)

- Таблица задач в ячейках: `TASK_TABLE 0x00A10000`, 32 слота (лимит спеки:
  32–64 МБ), слот = 8 честных слов:
  0: `tid`, 1: `state` (0 IDLE-FREE / 1 READY / 2 RUNNING / 3 SLEEPING /
  4 ZOMBIE), 2: `prio` (0..31, честная группа), 3: `entry` (адрес функции),
  4: `pc_cell` (куда VM пишет сохранённый PC при паузе), 5: `parent`,
  6: `retcode`, 7: `vruntime` (счётчик спринта А: честное накопление,
  выбор по минимуму — уже код ядра, VM не трогается).
- Текущая задача: ячейка `CUR_TASK 0x00A10100` (индекс слота или `NUL_TASK`,
  честное «задач нет»), контекст ядра — слот 0 (kthread планировщик).
- Очередь готовых — честный связный список: слово `next` (индекс слота),
  голова — ячейка `READY_HEAD 0x00A10104`; в спринте А честно
  32 слота, переполнение — честный брак TASK_LIMIT (0xF1).

## Честные NID-дополнения VM (адитивные, бэк-компат)

Контракты syscall-слоя как в честном файловом слое: адрес аргумента передаётся
через `STREAM_EMIT_CELL 0x00F00FF0` (уже честная ячейка-аргумент sys_call).

| NID | Честный смысл |
|---|---|
| 0x150 WORK_CTX_SAVE | сохранить контекст текущей задачи (pc, rts) по честному указателю из Stream_Emit |
| 0x151 WORK_CTX_RESTORE | загрузить контекст по честному указателю и продолжить с него |
| 0x152 WORK_CTX_YIELD | честный возврат в ядро-контекст (слот 0): VM сохраняет pc/rts текущей задачи и возобновляет ядерный контекст |

**Честный контракт блока контекста (VM-реализация, 2026-11-08):**
магия `'CTX1' 0x43545831`, раскладка `+0 magic, +1 pc, +2 acc, +3 rts_len,
+4..` rts-слова (в честном порядке списка VM, лимит глубины 0x80).

**Честные семантики эпох (реализовано в VM, честно
проверено на `schedF_test.kt/.ctos`):**
- WORK_CTX_RESTORE **переустанавливает ядерный контекст каждую эпоху**:
  точка возврата YIELD всегда = pc+5 после syscall RESTORE (состояние
  планировщика: pc, acc, rts).
- WORK_CTX_YIELD при установленном `kernel_ctx`: снимок задачи (pc+5, acc,
  rts) в блок → возврат в ядерный контекст, `kernel_ctx` честно очищается
  (следующий RESTORE честно переустановит).
- WORK_CTX_YIELD при `kernel_ctx=None` (честный fresh-старт задачи через
  `run Task_Body()`): снимок задачи ВКЛЮЧАЯ кадр вызова, честное снятие
  одного кадра — возврат в точку после run-вызова ядра (пре-роллинг).

**Честный контракт регистров:** все переменные стадии-0 живут в ОБЩЕЙ
памяти ячеек VM — переключение контекста сохраняет только pc/acc/rts.
Честная задача после каждого RESUME обязана заново вывести свой стейт из
честного контр. блока/meta (честный паттерн: `CUR_CTX → +160 slot →
Slot_Addr → +162 job`), регистры регистр — ячейки общие.

Браки честные `VmFault`: нет открытого протокола аргумента
(Stream_Emit = 0), magic блока не 'CTX1', rts_len сверх честного
лимита, pc вне потока опкодов (реализовано, проверено честным
негативом `Python_compiler/neg_ctx1.kt` — честный KERNEL PANIC,
exit 1).

## Честные браки ядра (первые честные коды спринта А)

- 0xF1 TASK_LIMIT — нет свободного слота (лимит спеки, 32).
- 0xF2 TASK_NOT_FOUND — spawn/join по несуществующему tid.
- 0xF3 TASK_STATE — некорректное состояние перехода (join не READY/ZOMBIE).

## Честные тест-фазы стенда (kernel.ctos, стадия-0)

Ф-А1: spawn одной задачи → исполнение до exit → честный ZOMBIE в ячейке слота.
Ф-А2: yield — VM честно сохраняет/восстанавливает контекст, порт печатает
череду задач (обмен через честные ячейки-флаги).
Ф-А3: join — родитель честно спит на очереди ожидания, честное
пробуждение от retcode задачи.
Ф-Н1..Ф-Н2: честные негативы (брак TASK_LIMIT при spawn 33-й задачи;
join несуществующего tid) — честный exit 0 с честным Fail_Code.

## Границы спринта А (честно позже, отдельные спринты)

- квант/вытеснение (спринт Б), мьютексы/nice (В), зачистка memory.ctos (Г);

## Правило проверки тестов

Каждая фаза пишет маркер в честные ячейки 0x90xx, честная трасса VM и
честный байт-отчёт артефакта — как в стендах TKT-052/TKT-054; честный
вердикт: 0xFF при успехе, 0xFE при браке.
