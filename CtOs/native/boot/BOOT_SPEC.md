# A3b/A4a — сырой legacy-BIOS загрузчик и нативный рантайм CtOS (эмуляционная контрольная точка)

Статус: ✅ A3b принят и ✅ A4a принят **в QEMU** (2026-11-18). ❌ **На железе не принято**: доступа к Acer Aspire Revo R3700 нет, моноблок без интернета. QEMU ставился только на хосте (`winget`, `SoftwareFreedomConservancy.QEMU` 11.1.0) как эмуляционная контрольная точка и **не заменяет** приёмку на моноблоке. UEFI/GRUB на целевой машине не подтверждены; путь — только legacy BIOS.

Связано: `CtOs/BRINGUP_SPEC.md` (Ф2/Ф3), `CtOs/native/NATIVE_RT_SPEC.md`, `Python_compiler/verify_boot_image.py`.

## 1) Что реально исполняется

Полный путь без псевдокода и без заглушек:

1. **MBR** (LBA 0, entry `0x7C00`, 188 Б кода + сигнатура `55 AA`). Проверяет EDD через `INT 13h AH=41h` (`BX=55AA` → `BX=AA55`, `CX bit0`), затем `INT 13h AH=42h` читает 4 сектора stage2 в `0x1000:0000` и передаёт управление `ljmp $0x1000,$0`.
2. **Stage2** (LBA 1..4, 1136 Б). Инициализирует COM1 (115200 8N1), печатает `CTOS A3b STAGE2` в VGA text и COM1, повторно проверяет EDD (номер диска берётся из сохранённой переменной — `INT 10h` портит `DL`), читает 64 сектора CTMD с LBA 8 в `0x2000:0000`.
3. Проверяет magic `CTMD`, версию/число модулей, каталог (48 Б на запись), границы тела и CRC-32 каждого из 4 модулей. Печатает имя и `CRC OK` / `CRC FAIL`; при браке — `CTMD FAIL` и отказ `AX=0x11`.
4. **A4a-загрузка PM**: EDD `AH=42h` читает 64 сектора с LBA 72 в `0x4000:0000` (физ. `0x40000`). Отказ чтения — `AX=0x11`.
5. **Защищённый режим**: `lgdt`, `cli`, `CR0.PE=1`. Переход в PM-рантайм — явный 32-битный far jump `EA <offset32> <sel16>` на линейный адрес `0x40000` (селектор `0x08`). Два честных бага найдены трассой QEMU `-d in_asm,int` и исправлены:
   - 16-битная форма `EA` уходила по VMA-метке в `0x50000` (метки stage2 имеют VMA 0, но исполняются по `0x10000`);
   - префикс `0x66` в `.code32` переключает far jump в 16-битный вариант, поэтому в `.code32` нужен **голый** `EA`.
6. В PM `_start` (`pm_start.S`) ставит плоские CS/DS/ES/SS, стек `0x90000`, обнуляет BSS по линкерным символам `_bss_start`/`_bss_end` (BSS по `0x01000000`, вдали от стека и VGA `0xB8000`) и вызывает `_main(5, argv)` с argv `native_rt --module memmgr CTMD:image events:com1`.
7. **Тот же `CtOs/native/native_rt.c` без правок семантики** компилируется в flat 32-bit PM-код с `-ffreestanding -nostdinc -mno-mmx -mno-sse -mno-sse2` (иначе GCC выдаёт `pcmpeqd %xmm3,%xmm3` и QEMU падает `#UD` при `CR4=0`). `pm/shim.c` подменяет **только libc**: `FILE` в памяти для CTMD и артефактов, COM1 для event'ов и `FATAL`, bump-allocator, минимальный `snprintf`/`fprintf`. Символов `nm -u` в PM-рантайме нет — builder это проверяет.
8. Успех `main()==0` ⇒ `isa-debug-exit AX=0x13` (rc=39). Отказ `verify_code()` / `fatal()` ⇒ `exit(1)` ⇒ `AX=0x14` (rc=41). COM1-лог после `CTOS A4a EXEC` байт-в-байт совпадает с хост-запуском `native_rt.exe --module memmgr`.

## 4) Коды `isa-debug-exit` (только QEMU-хук, не часть железа)

| AX | rc QEMU | Смысл |
|---:|---:|---|
| `0x10` | 33 | старый A3b-успех: PM достигнут, VGA прочитан, `PM OK` в COM1; больше не основной путь |
| `0x11` | 35 | честный отказ stage2 (нет EDD / read fail / magic / CRC / CTMD FAIL / PM read fail) |
| `0x12` | 37 | честный отказ MBR (нет EDD / read fail) |
| `0x13` | 39 | успех A4a: PM-рантайм отработал, event-лог совпал с хостом |
| `0x14` | 41 | runtime-fatal: `verify_code()` / `fatal()` / `exit(1)` внутри PM-рантайма |

Верификатор удаляет лог перед каждым запуском и строит в отдельном TEMP-каталоге. Имя лога — `serial.log`, **не** `com1.log`: на Windows `COM1` — зарезервированное имя устройства, `os.remove` по такому пути падает с `WinError 5`. Перед каждым хост-запуском удаляется `<binary>.out`.

## 6) Честные границы

- QEMU — эмуляционная контрольная точка. «Заработало на R3700» **не заявляется**: реальной загрузки с диска на моноблоке не было.
- `isa-debug-exit` — тестовый хук QEMU, на железе он не завершает машину честно; для реального стенда нужен отдельный путь завершения/передачи управления ядру.
- A4a исполняет **только `memmgr`** в PM. Остальные модули CTMD (`sched`, `syscall_test`, `stage1`) проверены по CRC в stage2, но в PM не запускались; полная самосборка `S(S_T)` остаётся хостовым A1/A2/A3a-гейтом.
- A4a меняет только libc-окружение: семантика `native_rt.c` не тронута, в PM нет настоящей файловой системы, прерываний и HAL физической памяти.
- MBR-отказ `rc=37` запрограммирован, но в автоматический верификатор не включён: автоматически проверяются magic/CRC-негативы stage2 и runtime-fatal.
