# A3b — сырой legacy-BIOS загрузчик CtOS (эмуляционная контрольная точка)

Статус: ✅ A3b принят **в QEMU** (2026-11-18). ❌ **На железе не принято**: доступа к Acer Aspire Revo R3700 нет, моноблок без интернета. QEMU ставился только на хосте (`winget`, `SoftwareFreedomConservancy.QEMU` 11.1.0) как эмуляционная контрольная точка и **не заменяет** приёмку на моноблоке. UEFI/GRUB на целевой машине не подтверждены; путь — только legacy BIOS.

Связано: `CtOs/BRINGUP_SPEC.md` (Ф2/Ф3), `CtOs/native/NATIVE_RT_SPEC.md`, `Python_compiler/verify_boot_image.py`.

## 1) Что реально исполняется

Полный путь без псевдокода и без заглушек:

1. **MBR** (LBA 0, entry `0x7C00`, 188 Б кода + сигнатура `55 AA`). Проверяет EDD через `INT 13h AH=41h` (`BX=55AA` → `BX=AA55`, `CX bit0`), затем `INT 13h AH=42h` читает 4 сектора stage2 в `0x1000:0000` и передаёт управление `ljmp $0x1000,$0`.
2. **Stage2** (LBA 1..4, 1056 Б). Инициализирует COM1 (115200 8N1), печатает `CTOS A3b STAGE2` в VGA text и COM1, повторно проверяет EDD (номер диска берётся из сохранённой переменной — `INT 10h` портит `DL`), читает 64 сектора CTMD с LBA 8 в `0x2000:0000`.
3. Проверяет magic `CTMD`, версию/число модулей, каталог (48 Б на запись), границы тела и CRC-32 каждого из 4 модулей. Печатает имя и `CRC OK` / `CRC FAIL`; при браке — `CTMD FAIL` и отказ.
4. **Защищённый режим**: `lgdt`, `cli`, `CR0.PE=1`, затем **32-битный far jump** `66 EA <offset32> <sel16>` с линейным адресом `stage2_base + pm_entry = 0x1019A`. Плоский код-сегмент имеет base=0, поэтому 16-битный far jump (`EA 9A 01 08 00`) ушёл бы по физическому `0x19A` в мусор и дал `#UD` — этот баг найден трассой QEMU `-d in_asm,int` и исправлен.
5. В PM: плоские CS/DS/ES/SS, стек `0x90000`, строка `CTOS A3b PM OK` пишется в VGA text (`0xB8000`, атрибут `0x1F`) и **перечитывается** для честной проверки, затем дублируется в COM1. Успех — `isa-debug-exit` с `AX=0x10`.

## 2) Раскладка образа (512 Б/сектор, всего 128 секторов = 65536 Б)

| LBA | Содержимое | Адрес исполнения/загрузки |
|---|---|---|
| 0 | MBR: 188 Б кода + `55 AA` | `0x7C00` |
| 1..4 | stage2 (4 сектора, 1056 Б из 2048) | `0x1000:0000` (физ. `0x10000`) |
| 5..7 | нули (зарезервировано) | — |
| 8..71 | CTMD v1: 64 сектора, 28425 Б | `0x2000:0000` (физ. `0x20000`) |
| 72..127 | нули | — |

Образ и промежуточные `*.bin` в VCS не идут: `build_boot_image.py` воспроизводит их из `mbr.S` / `stage2.S` / CTMD.

## 4) Коды `isa-debug-exit` (только QEMU-хук, не часть железа)

| AX | rc QEMU | Смысл |
|---:|---:|---|
| `0x10` | 33 | успех: PM достигнут, VGA прочитан, `PM OK` в COM1 |
| `0x11` | 35 | честный отказ stage2 (нет EDD / read fail / magic / CRC / CTMD FAIL) |
| `0x12` | 37 | честный отказ MBR (нет EDD / read fail) |

## 5) Таблица приёмки

| Случай | Команда | Ожидание | Статус |
|---|---|---|---|
| холодная сборка ×2 | `python -X utf8 Python_compiler/verify_boot_image.py` | `deque cold x2 … IDENTICAL` | ✅ |
| positive QEMU | то же | `rc=33`, 8 строк лога от `CTOS A3b STAGE2` до `CTOS A3b PM OK` | ✅ |
| negative: магия | то же | правка `CTMD`→`XXXX` в LBA8 ⇒ `rc=35`, `CTMD magic FAIL` | ✅ |
| negative: CRC | то же | порча байта тела `memmgr` ⇒ `rc=35`, `CRC FAIL` + `CTMD FAIL` | ✅ |
| A1/A2/A3a регресс | `python -X utf8 Python_compiler/verify_native_rt.py` | `NATIVE RT OK A1/A2/A3` | ✅ |
| компилятор | `python -X utf8 Python_compiler/regr120.py` | `REGRESS OK … FIXPOINT`, `cold: IDENTICAL` | ✅ |

Верификатор удаляет лог перед каждым запуском и строит в отдельном TEMP-каталоге. Имя лога — `serial.log`, **не** `com1.log`: на Windows `COM1` — зарезервированное имя устройства, `os.remove` по такому пути падает с `WinError 5`.

## 6) Честные границы

- QEMU — эмуляционная контрольная точка. «Заработало на R3700» **не заявляется**: реальной загрузки с диска на моноблоке не было.
- `isa-debug-exit` — тестовый хук QEMU, на железе он не завершает машину честно; для реального стенда нужен отдельный путь завершения/передачи управления ядру.
- Нативный интерпретатор `.ctos` ещё не запущен из PM: A3b проверяет загрузку и целостность модулей, но не исполняет их в защищённом режиме (это Ф3).
- Таймер/IRQ, HAL физической памяти, установщик на диск — не сделаны.
- MBR-отказ `rc=37` запрограммирован, но в автоматический верификатор не включён: автоматически проверяются magic/CRC-негативы stage2.
