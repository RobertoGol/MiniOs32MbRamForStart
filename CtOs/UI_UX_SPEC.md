# CtOS UI/UX Spec (черновик)

Дата: 2026-11-21  
Статус: черновик, docs-only, не реализовано.  
Связан: `CtOs/SD_SHELL_SPEC.md`, `CtOs/BRINGUP_SPEC.md`.

## 1. Цель

Зафиксировать направление UI/UX для CtOS: оболочка, локальные профили, вход, меню настроек, визуальный стиль и правила переключения тем/профилей оформления.

## 2. Визуальное направление

| Профиль | Статус | Назначение | Описание |
|---|---|---|---|
| **CtOS Base** | **база по умолчанию для внутренней разработки/для нас** | Внутренний эталон, отладка, контроль читаемости и собственная идентичность | Собственный минималистичный стиль CtOS: простые формы, высокая читаемость, низкая зависимость от анимаций, удобен для отладки и низких ресурсов. |
| **PSP/PS3-inspired** | **профиль для релиза** | Пользовательский релизный облик | Вдохновлён XMB/консольной навигацией PSP/PS3: горизонтальные категории, вертикальные элементы, акцент на фокус/анимации/звуковую обратную связь. **Не полная копия** и не использование фирменных ассетов Sony. |

Правила:
- Внутренняя база и релизный профиль — разные профили оформления/поведения оболочки, а не разные продукты.
- PSP/PS3 — ориентир по ощущениям и навигации; иконки, шрифты, звуки, брендинг и ассеты должны быть собственными или совместимыми по лицензии.
- Любой визуальный эффект должен иметь деградацию: при слабом GPU/режиме отладки/низкой производительности UI остаётся функциональным.

## 3. Локальный профиль и вход

- Система поддерживает локальные аккаунты (минимум: системный/служебный и обычный пользователь).
- Обычный пользователь может быть создан **без пароля** для первичной настройки (“любой может войти до настройки пароля”).
- После первого входа UI предлагает настроить защиту профиля, но не делает это скрытым/навязчивым разрушительным действием.
- Анимация входа в локальный аккаунт должна быть красивой, но короткой и прерываемой; при слабом устройстве/режиме отладки — упрощённый вариант.

## 4. Меню профиля

- В правом верхнем углу — значок-шестерёнка профиля.
- Подменю профиля (минимум):
  - **Профиль** — имя, аватар/значок, локальный статус.
  - **Настройки профиля** — язык, тема/профиль оформления, анимации, звук UI.
  - **Безопасность** — установить/сменить/убрать пароль, автозаблокировка, подтверждение при запуске недоверенного SD-контента (если включено).

## 5. Связь с SD-shell

- SD-shell/библиотека (см. `SD_SHELL_SPEC.md`) отображается как источник контента, но не должна незаметно подменять базовые настройки безопасности.
- Приоритет SD-оболочки (решение SD-shell draft) должен учитывать профиль оформления: можно показывать контент/оболочку с SD, но базовые системные действия (безопасность, fallback, журнал) остаются доступными.
- Если SD-оболочка несовместима с текущим UI-профилем, используется fallback на резервную оболочку SSD.

## 6. Ограничения честности

- Это черновик UI/UX; в CtOS пока нет реализованного GUI, профилей пользователей, анимаций входа, меню настроек.
- “PSP/PS3-inspired” не означает совместимость с PSP/PS3, запуск их игр, или использование их защищённых ассетов.
- Любое поведение безопасности должно быть явным: пустой пароль — осознанное состояние, а не тихая уязвимость без индикации.

## 7. Открытые вопросы

1. Где хранится профиль пользователя: на SSD, на SD, или оба с приоритетом?
2. Какой формат темы/оболочки: пакет ресурсов + манифест + ограничения?
3. Нужен ли гостевой режим отдельно от обычного пользователя без пароля?
4. Как переключать Base/PSP-PS3-inspired: глобально, на профиль, или по источнику загрузки?
5. Какие минимальные требования к анимациям на R3700/ION2, чтобы UI не деградировал?
6. Как показывать предупреждение при запуске SD-оболочки/контента без подписи (signature OFF по умолчанию)?

## 8. Первые гейты (будущие)

- **UI-G1:** текстовая спека профилей оформления и состояний экрана входа.
- **UI-G2:** прототип меню в QEMU/host с Base-профилем.
- **UI-G3:** PSP/PS3-inspired профиль как отдельный пакет темы, без замены Base.
- **UI-G4:** локальный профиль + пустой пароль + настройка пароля в “Безопасность”.
- **UI-G5:** интеграция с SD-shell fallback и индикаторами источника (`SD`/`SSD`).
