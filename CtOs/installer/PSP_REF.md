# 📦 PSP_REF: реальный PSP-экосистемный корпус как образец дистрибутива CtOs

Корпус скачан в `F:\PSP_OS` (вне репозитория — только анализ; бинарники в git не кладём).
Четыре экспоната и что каждый нам честно даёт.

## 1. ARK-4 (`ARK4/`) — Live/Permanent CFW, главный референс
Ключевые файлы: `README.TXT`, `ARK_01234/` (модули), `ARK_Loader/` (EBOOT.PBP),
`PSVita/FasterARK.vpk`, `themes/`, `UPDATE/EBOOT.PBP`.

Честные уроки для INSTALL_SPEC (совпадения с нашей спекой — подтверждение пути):

1. **«Live CFW» = наш run-from-media.** ARK грузится с Memory Stick каждый раз;
   «перманент» (cIPL) — отдельный шаг установки. У нас: ОС на SD/USB запускается
   прямо с носителя, «вшить во внутренний накопитель» — опционально. ✓ уже в спеке.
2. **Обновление из XMB.** README: `System Update feature in the XMB` — ровно наш
   GUI-маршрут `Settings → System Update`. ✓ уже в спеке.
3. **Fallback-цепочка размещения.** Нет Custom Launcher — «PRO Shell возьмёт его
   место»; нет savedata — настройки ищутся в `ms0:/SEPLUGINS/`. У реализации есть
   честная лестница fallback-адресов. Наше соответствие: `ms0:/CtOs/settings/`
   → при отсутствии носителя — внутренняя память, каждое решение — запись в
   журнал Early Boot.
4. **Приоритет загружаемых файлов.** «Even if files are stored in flash, the ones
   in the savedata folder will still take priority in loading» — кто где важнее.
   Наше правило то же духом: тема в `themes/custom/` всегда бьёт `builtin/`. ✓.
5. **SETTINGS.TXT — эталон честного конфига** (файл `ARK_01234/SETTINGS.TXT`):
   строк `контекст, ключ, значение` + точечные исключения по коду игры:
   `ULUS10201, infernocache, off`. Итог для нас: одна система настроек должна
   уметь и глобальные дефолты (`always, overclock, on`), и per-приложение
   overrides. Закладываем в формат `ctos.conf` селектор контекста (`always`
   и имя/путь приложения): селектора сейчас нет — это честная задача спека.
6. **Ресурсные контейнеры**: `FLASH0.ARK`, `LANG.ARK`, `THEME.ARK` — ОС, модули
   и темы лежат «вёдрами» в своих архивах. Наша замена ОС = замена того самого
   файла; для PSP-базы плоский каталог безопаснее, но контейнер вида `CTOS.IMG`
   фиксируем опцией в INSTALL_SPEC («замена файла»).
7. **Плагины и Recovery**: `PLUGINS.TXT`, `RECOVERY.PRX`, `BSOD.PRX` — recovery
   живёт отдельным честным входом, а не на дне меню. Наш ТЕРМИНАЛ под Settings
   обязан играть роль recovery-оболочки (спека уже есть — корпус её подтвердил).

## 2. PRO CFW 6.20 (`620-PRO-2015-02-14_MOD-2015-03-33-F/`)
`seplugins/` — recovery-меню на 7 языках, включая **`recovery_ru.txt` (2673 байта)**.

Честные уроки:
1. **Русский recovery — признан нормой.** Даже сторонний CFW локализует
   recovery на русский списком строк-констант. Наша ОС обязана локализовать
   критические экраны (паники, recovery) с первых версий.
2. **Локаль = список коротких строк**, одна строка — одна метка интерфейса.
   У нас локали честно храним как таблицу строк, не как размеченные документы.
3. **Advanced VSH Menu**: `usbcharge`, `overclock`, `wpa2`, драйверы M33/NP9660/
   Inferno — пункты управления железом. Правило «ОС не парит железо» у нас
   задаёт приоритеты, поэтому такие пункты мы держим честно за флагами в
   конфиге, не обязательностью ради «богатых» стендов.

## 3. Официальная прошивка 6.61 (`Orig/661.PBP`, 32.58 МБ)
Чистый EBOOT.PBP OFW 6.61 — формальная калибровка веса: официальный
однобайтовый дистрибутив прошивки PSP = ~32.5 МБ. Наш бинарь ОС обязан
оставаться заметно меньше этого порядка (база PSP-1004 обещает 32 МБ RAM).

## 4. Lua-оболочка «Android» (`Android version/Android/`)
`SCRIPT.LUA` — честный образец scripted-shell на PSP: шрифт TTF, сетка
иконок приложений, boot-анимация кадрами `boot (N).jpg`, файл настроек
`option.lua`. Интерпретируемая оболочка на слабом железе работает, но мы
честно НЕ берём этот путь: наш слой обязан компилироваться KINII (стадия-0).
Берём только UX-идеи: сетка иконок, поток настроек, дешёвая кадровая
анимация загрузки вместо декодера видео (в слабых стендах кадры дешевле,
чем у нас `boot.webm` — он остаётся опционалом).
