# 🖥️ Bootlog + Fastfetch — честный загрузочный лог и сведéние системы

Место: `CtOs/boot/`. Статус: спецификация (реализация — стадия-0 честными
спринтами: сначала честный лог загрузки, fastfetch — «в конце», после
ядра/эмулятора).
Референсы: Linux bootlog ([ok]/[info] по времени), Pip-Boy Boot Terminal
(зелёный CRT, COPYRIGHT 2086 MUNCHKIN), SteamDeck boot video (.webm).

## Принцип: две честные «морды» загрузки

| Режим | Что видно | Как включается | Деградация |
|---|---|---|---|
| **bootlog** (по умолчанию) | честный текстовый лог стадий: `[ ok ]`/[info]/[warn] | всегда, любой сбой честно виден | зелёный текст на чёрном (CRT-стиль Pip-Boy) |
| **boot video** | короткий ролик `.webm` (VP8/VP9), по темам | `Settings → Theme`, гасится `rootcmd: boot.video off` (спринт Rootcmd уже даёт честный флаг) | ролик отсутствует → честный fallback на bootlog, система не падает |

Правило честности: boot video — это **косметика поверх** bootlog. Лог
пишется в журнал ВСЕГДА (лог — подстилка под роликом), ролик рисуется при живом
флаге `Boot_Vid = 1`. Краш при загрузке ролика → мгновенный переход на
текстовый bootlog (честный аварийный вывод).

## Формат строки bootlog (честный, как на скриншотах)

```
[tick 0004120] [ ok ] планировщик А-Д: таблица задач сходится (12 опкодов/тик)
[tick 0004350] [info] монтирование носителей: ms0: SD, ms1: USB1, hd0: SATA
[tick 0004380] [warn] USB2: порт пустой — честно пропущен
[tick 0004800] [ ok ] темы: builtin/ps5_style применена (деградация честная)
[tick 0005100] [ ok ] оболочка XMB: волна честна, иконки плоские
```

* метка времени — `Tick_Counter` ядра (No-HZ честен: тиков во сне нет);
* три честных уровня: `[ ok ]` — стадия сошлась, `[info]` —
  уведомление, `[warn]` — пропущено/деградировало без паники;
* паника ядра — отдельный честный режим (`[FAIL]` + дамп ячеек) и
  останавливает загрузку (не «зелёная простыня», а честная точка сбоя).

## Стадии bootlog (порядок честной загрузки)

1. `power` — честная проверка питания/батареи (спринт Powermanagment).
2. `kernel` — ядро, кольца 0–2, барьер 0x00A00000.
3. `scheduler` — А–Д: таблица задач, кольцо готовых, мьютексы,
   аллокатор, No-HZ.
4. `bridge` — `bridge.ctos`: порты дисков (энумерация из спринта
   Монтирование), ввод.
5. `mount` — честные маршруты `ms0:`/`hd0:` + одноразовый честный скан
   ISO/Games/Save (см. EMULATION_SPEC).
6. `fs` — файловая модель, magic-разбор файлов.
7. `themes` — база + builtin/custom (спринты Темы/Builtin честны).
8. `apps` — рантайм приложений, терминал, CtMusic.
9. `shell` — XMB готов; лог завершается и сворачивается (остаётся в
   журнале `BOOT_LOG`).

Пункт 6 и далее — честный журнал в памяти: `BOOT_LOG 0x00E30000`,
записи (tick, уровень, код стадии) — 12 байт, до 256 записей.

## Fastfetch-аналог (в конце, честные источники уже есть)

Команда терминала `fetch` + экран `sysinfo` (обе честно сводят одни и те
же ячейки ядра — ноль собственного «вранья»):

```
CtOs 2.0 (KINII-подмножество стадии-0)
──────────────────────────────────────
Ядро:        CtOs 2.0.0 (планировщик А-Д закрыт, No-HZ)
Железо:      ACER Revo R3700, 13 Вт потолок (Design Law)
CPU/бесс.:   честный счётчик тиков + честный лимит Mem_Pool
Носители:    ms0: SD жив, ms1: USB1 жив, hd0: SATA жив
Папки игр:   ISO/Games/Save найдены одноразовым сканом (EMULATION_SPEC)
Тема:        builtin/ps5_style (флаги деградации = 0)
Аптайм:      Tick_Counter / честный темп тиков
Графика:     2D-плоскость честна, волна честна; 3D — по EMULATION_SPEC
```

Правило: если данных нет (сетевая карта не поднялась) — честное `—`,
без подделки. Цвет названия — акцент текущей темы из `SHELL_PAL`.

## Честные ограничения стадии-0

* webm-ролик и CRT-стиль — прикладной слой; стадия-0 даёт только
  честные флаги/журнал (уже честно: `Boot_Vid`, `BOOT_LOG`).
* `fastfetch` НЕ станет частью ядра: это приложение, читающее ячейки.
