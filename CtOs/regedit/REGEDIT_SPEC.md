# 🗂️ REGEDIT_SPEC — честный реестр CtOS (дерево конфиг-ячеек, НЕ Hive)

Место: `CtOs/regedit/`. Статус: спека + **реализация стадии-0**
(`CtOs/regedit/regedit.kt` → `regedit.ctos`, 2026-11-01,
[[TKT-039_regedit_ctos]]). UI TreeView — прикладной слой CtMusic.

## Модель

Реестр CtOS — честное дерево конфиг-ячеек в системной области Ring 0.
Формат **совпадает с ФС**: слово 4 байта (`& 0xFFFFFFFF`, см. BUGS.md B-13)
→ ОДИН слой чтения и для TkRegEdit, и для TkExplorer.

Узел — 24 байта:

| Смещение | Поле | Смысл |
|---|---|---|
| +0 | id | честный номер узла (уникальный) |
| +4 | parent | родитель (0 = корневая ветка) |
| +8 | tag | имя ветки/значения, 4 ASCII-символа LE |
| +12 | type | 1 = DWORD (слово); 2/3 = строки/списки — с текстовым слоем |
| +16 | value | честное значение (для DWORD) |
| +20 | rights | 0 = RW (запись Ring 0), 1 = RO (не пишется никем) |

Корневые ветки вместо `HKEY_*`: **SYS\\** (ядро/планировщик/загрузка),
**USR\\** (пользователь/тема/волна), **APP\\** (приложения/терминал/CtMusic),
**HW\\** (профиль железа/пул/энергосбережение).

## Честные правила

- **Запись — только Ring 0** (привилегированный syscall). Ниже колец —
  честный отказ `0x7060`, значение НЕ меняется.
- **Read-only значения** (версия ядра, контрольное слово, профиль, MAC) —
  честный отказ `0x7061`.
- **Нет узла** — честный отказ `0x7062`.
- **Каждое изменение** — пара `(узел, старое, новое)` в журнал `REG_LOG`
  (12 Б на запись, до 64 записей) — по образцу rootcmd-журнала.
- **Адресная строка** — честный префикс-поиск ветки: родитель + имя
  (без строки «путь целиком» — её соберёт UI).
- **Поиск** — по дереву в памяти (мгновенный, не polling — правило
  слабого железа).
- **Экспорт/импорт** — честный блочный формат `REG1`
  (`magic + число узлов + узлы по 24 Б`). Текстовый формат бэкапа — с
  текстовым слоем (честно позже, не подделываем строки).
- **Целостность** — контрольное слово = сумма всех слов дерева (32-бит);
  честная сверка ловит порчу в обход syscall и честно восстанавливается.

## Реализация стадии-0 (2026-11-01)

`regedit.kt` (5225 Б, 12300 опкодов, VM exit 0), дерево из 20 узлов:

| Ветка | Значения |
|---|---|
| SYS | KERN 0x200 (RO), TASK 8 (RO), NOHZ 1, BOOT 1, SEAL 1 (RO) |
| USR | NICK (тип 2, пусто), MAC (RO), THEM 3, WAVE 1 |
| APP | TERM 1, CTMS 1, CUST 0 |
| HW | PROF 2 = R3700 (RO), MEM 32, GOV 0, THRM 0 |

Проверено живьём: 20×24 Б, курсор `0x00E601E0`; префикс-поиск `APP\TERM` = 13;
поиск `THEM` = 10; Ring 2 читает версию ядра; запись из Ring 2 отвергнута
(значение 3 цело); запись в RO отвергнута; запись из Ring 0 `THEM 3 → 1`
легла и журнал честно `(10, 3, 1)`; неизвестный узел отвергнут; экспорт
`REG1` — 6 узлов `SYS\` (id 1..6); импорт равен ветке; контрольное слово
`0xDD99B07D` сходится с независимым пересчётом 120 слов; порча `0xDEAD`
честно поймана и восстановление вернуло OK; общий `Read_Word` отдаёт то же
значение (один слой для RegEdit и Explorer).

## Честный остаток

- Текстовый экспорт/импорт (строковые имена, комментарии) — текстовый слой.
- UI TreeView/колонки/адресная строка с автодополнением — CtMusic.
- Строки/списки (`type 2/3`) как настоящие данные — текстовый слой.
- Настоящие syscall'ы по кольцам на железе — с freestanding-ядром.
